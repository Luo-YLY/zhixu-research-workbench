# V0 基础架构与阶段计划

## 职责

- Vue 负责展示、输入及人工操作。前端不自行判定研究结果通过，也不直接读数据库。
- Spring Boot 负责输入校验、业务状态、审批及审计事件。
- PostgreSQL 是正式目标数据库；H2 文件配置用于便捷本地开发。
- V0 的持久化实现使用 Spring JDBC + Flyway，SQL、事务和表结构可以直接对照阅读；Controller、业务服务与存储职责分开。后续是否引入 JPA 不影响前端接口。
- 后台 Runner 读取已持久化的运行，执行固定版本的工作流。V0 只有确定性 DEMO 处理器。
- 产物写入项目数据目录，数据库记录文件名、相对位置、大小和 SHA-256。

## 一次请求

Vue 发出启动请求 → Controller 接收 → 服务在事务内检查任务、重复键与活动运行 → 写入运行、节点及事件 → 返回运行详情 → Runner 异步推进 → 数据库持久化事件 → SSE/轮询更新页面。

人工批准是一个独立事务；批准记录与节点状态更新一起提交。仅批准后 Runner 才进行最终归档。重复审批、终态取消等非法状态转换返回冲突。

## V0 的取舍

固定的五节点模板承担第一条可验收流程；本版没有通用 DAG 编辑器、动态脚本节点、任意工具执行或多机任务抢占。所有活动执行状态写入数据库，安全的示例节点允许在进程重启后恢复。

实际外部研究工具上线时，需要进一步设计领取租约、心跳、超时、取消、幂等键和重试策略。数据库事务不能撤销外部工具产生的副作用；不能把 DEMO 的恢复逻辑直接套用到真实外部操作。

## 逐阶段接入

V0.2 已增加独立的上下文讨论助手：Vue 侧栏 → 持久化助手队列 → AssistantGateway → 可选模型适配 → 用户编辑确认的任务草稿。默认 provider=disabled，不调用任何模型；已预留 Codex App Server 和兼容 Chat Completions API 适配。下表 V1 指研究节点内的真实执行器，尚未接入。详见 [助手设计](ASSISTANT.md)。

V0.3 已先落地日常安排的独立闭环：任务周期规则 → 按北京时间生成当天待办 → 人工完成／重新打开 → 数据库存档。打开某日页面和每天零点都可补齐该日到期事项；同一规则同一天只生成一次。暂停仅阻止后续生成，不清除既有待办。周期规则当前不启动 DEMO 运行；真实研究自动执行、漏执行补偿和通知须等执行器有可验证的安全边界后再设计。

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| V0 基础 | 项目、任务、持久化流程、审批、事件、产物 | 本地完成批准/退回/取消并验证重启 |
| V1 执行器 | Codex/Python 适配器、工作目录、超时与取消 | 一个固定任务真实执行，保存命令版本及输入输出 |
| V2 证据 | 已实现 PDF/TXT/Markdown 入库、哈希和物理页码引用；后续补 OCR 与结构化提取 | 每条引用回到原文件且保留版本 |
| V3 RAG | 已实现版本化词法基线及可选模型回答；后续补混合检索和固定评测集 | 固定问题集评估召回和引用，不以流畅文本验收 |
| V4 自动调度 | 真实执行触发、漏执行补偿、通知与异常处理 | 重启、重复触发与时区案例通过；V0.3 的待办生成是此前置能力 |
| V5 协作 | 登录、权限、角色、独立复核、多 Agent | 验证跨项目隔离和审计再开放多人访问 |

原始文件、行情与研究产物按用途存储。数据库先管理可查询的结构化信息和版本引用；不把全量市场数据塞进向量库。
